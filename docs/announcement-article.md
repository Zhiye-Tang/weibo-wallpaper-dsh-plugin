## 正文

### 起因:我想要一个"会更新"的壁纸

我每天都用 DSH(DeepSeek Harness)写代码。某天我忽然想:如果这个 Web 界面背后能显示喜欢的博主的相册,每次打开都像翻了一页新的"今日份好看",会不会很解压?

市面上壁纸工具很多,但"从一个不断更新的内容源里取壁纸"这件事,基本没有现成方案。而 DSH 本身是 Cordis 组合出来的——每个能力都是插件——那我为什么不自己写一个呢?

于是有了 [weibo-wallpaper-dsh](https://github.com/Zhiye-Tang/weibo-wallpaper-dsh-plugin):一个把微博博主相册/微博媒体变成 DSH Web 界面壁纸的宿主插件。**纯 Node 原生实现、零 npm 运行时依赖、随 DSH 进程常驻、打开即显示。**

我喜欢走路摇ZLY，所以我默认的博主相册就是她的，你可以根据你的喜好将其他博主的相册作为你DSH壁纸。

### 它能做什么

- **按天幂等检查**:同一天重复打开 DSH → 秒开,完全不访问微博;跨天/新内容 → 增量下载。
- **按月归档**:每月自动新建 `YYYY-MM` 文件夹,历史内容按月份整整齐齐躺在本地。
- **历史回填**:首次启用自动把今年 1 月到上个月全部归档,断点续传,中途关掉不丢进度。
- **多博主**:改一行配置就能同时跟踪多位博主,控制条下拉即切换。
- **三种显示模式**:● 全遮挡(关掉壁纸)/ ◐ 毛玻璃(默认)/ ◯ 全透明——在控制条上循环切换,不用改任何配置文件。
- **免手动刷新**:引擎挂载在 profile(进程)层,壁纸层由引导脚本自举,打开页面即是壁纸。

### 十秒钟上手

1. 把仓库 `plugins/` 下两个插件目录复制到你的 DSH profile 目录(如 `~/.dsh/profiles/web/`);
2. 把 `install/cordis.patch.snippet.yml` 里的 `- insert:` 合并进 profile 的 `cordis.patch.yml`;
3. 复制 `config.example.json` 为 `config.json`,填一个本地保存目录;
4. **重启 DSH** → 页面右下 🔑 粘贴你的微博 Cookie(m.weibo.cn 登录后 F12 复制)→ ⟳ 验证。

完成。之后每次打开 DSH,壁纸自动是博主的最新内容。

### 有意思的实现细节

写这个插件的过程中踩过不少坑,分享三个我觉得最有价值的:

**① 会话级能力 vs 宿主级能力。** 第一版我把引擎挂在 agent 预设里,结果发现:壁纸依赖"某个会话恰好开着",会话一关路由就 404。后来把引擎改造成 profile 补丁层(随进程启动),才真正做到"打开 DSH 就有壁纸,与任何会话无关"。Cordis 的两层组合(宿主组合 vs 预设)边界,值得每个 DSH 插件作者先想清楚。

**② 微博移动端接口的翻页玄学。** 观察对象的微博流容器响应里**永远没有 `since_id`**(因为一条置顶旧微博把语义搞乱了),一开始按 `since_id` 翻页导致历史回填只抓了第一页。改成按数字 `&page=N` 翻页、并用"整页都早于窗口下界"作为终止条件之后,回填才真正能跑到底——这个"接口行为会变、别写死假设"的教训很值。

**③ 一个容易让所有请求挂掉的坑。** DSH 每次模型请求都会解析所有活动的本地插件行,插件目录最近的 `package.json` 如果只有 `name` 没有 `version`,会抛 `REQUEST_EXTENSION`,**所有请求全军覆没**。所以每个本地插件目录都必须自带合法的 `package.json`。这个坑我写进了仓库的安装注释里,希望后来者别踩。

### 关于隐私,我把它写进了 README

需要说明的是:这类插件绕不开"Cookie"。我的处理是——

- Cookie 只保存在**你自己的本机** `<root>/<uid>/state.json`,代码不向任何第三方发送数据,网络只指向微博;
- 但它本质是你的登录凭据,**切勿**贴到 Issue、截图或聊天里;过期了就 🔑 重贴一次;
- 下载内容版权归原作者所有,请仅作个人本地自用,不要二次分发;
- 依赖的是微博非官方 JSON 接口,微博可能限流(`432`)、改版或封禁——插件内置了节流、失败跳过与断点续传,但无法承诺永远不被限。
